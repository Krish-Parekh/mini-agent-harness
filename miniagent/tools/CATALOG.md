# Tool catalog

Generated by `uv run python -m miniagent.tools.catalog`. This is exactly what the model sees for each built-in tool; MCP tools are added at runtime.

## `bash`

Run a shell command and return its stdout, stderr, and exit code. The command runs non-interactively with the workspace root as the working directory. Use it to explore (`rg -n "pattern" src/`, `git log --oneline -10`, `git diff`, `sed -n '40,90p' file.py`), to verify (`python -m pytest tests/test_x.py -x -q`), and for any multi-file or git work. Keep output small: prefer `| head -50` and narrow test invocations over full suites. Never start interactive commands (editors, REPLs, watch mode). The default `timeout` is 30 seconds; pass a larger value (120-600) for installs, builds, or test suites. Set `description` to a short summary of the command, and `workdir` instead of starting the command with `cd`. Before `rm` or `mv`, check the resolved target path, and guard variables with `${VAR:?}` so an empty value cannot widen the target. If the sandbox denies a command, do not retry the same effect another way.

```json
{
  "properties": {
    "command": {
      "title": "Command",
      "type": "string"
    },
    "description": {
      "default": "",
      "description": "5-10 word summary of what the command does, shown to the user.",
      "title": "Description",
      "type": "string"
    },
    "timeout": {
      "default": 30,
      "maximum": 600,
      "minimum": 1,
      "title": "Timeout",
      "type": "integer"
    },
    "workdir": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "description": "Directory to run in, relative to the workspace. Use instead of `cd x && ...`.",
      "title": "Workdir"
    }
  },
  "required": [
    "command"
  ],
  "title": "BashAction",
  "type": "object"
}
```

## `file_edit`

View, create, or edit a file in the workspace. command='view' returns the file's raw text exactly as stored (no line numbers); pass view_range=[start, end] (1-based, end -1 = EOF) for a slice. command='create' writes content to a new file (overwriting an existing file requires viewing it first). command='str_replace' replaces a unique old_str with new_str; old_str must match the raw file bytes exactly (copy from view output, never include line-number prefixes) and appear exactly once, so include enough surrounding context to be unique. Edit only files you have viewed in this conversation; if a file changed since your last view, view it again before editing.

```json
{
  "properties": {
    "command": {
      "enum": [
        "view",
        "create",
        "str_replace"
      ],
      "title": "Command",
      "type": "string"
    },
    "content": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "title": "Content"
    },
    "new_str": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "title": "New Str"
    },
    "old_str": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "title": "Old Str"
    },
    "path": {
      "title": "Path",
      "type": "string"
    },
    "view_range": {
      "anyOf": [
        {
          "items": {
            "type": "integer"
          },
          "type": "array"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "title": "View Range"
    }
  },
  "required": [
    "command",
    "path"
  ],
  "title": "FileEditAction",
  "type": "object"
}
```

## `present_plan`

Present a structured implementation plan to the user and pause for their review. Use this when planning mode is on: after exploring the code read-only, lay out the ordered steps, each with an imperative title, the files it touches, and a short description, then call this tool instead of editing files or finishing. The turn stops so the user can approve or refine the plan before you implement.

```json
{
  "$defs": {
    "PlanStep": {
      "properties": {
        "description": {
          "default": "",
          "description": "One or two sentences on what to do and why",
          "title": "Description",
          "type": "string"
        },
        "files": {
          "description": "Files this step touches",
          "items": {
            "type": "string"
          },
          "title": "Files",
          "type": "array"
        },
        "status": {
          "default": "pending",
          "enum": [
            "pending",
            "in_progress",
            "done"
          ],
          "title": "Status",
          "type": "string"
        },
        "title": {
          "description": "Imperative summary of the step, e.g. 'Add the lane column'",
          "title": "Title",
          "type": "string"
        }
      },
      "required": [
        "title"
      ],
      "title": "PlanStep",
      "type": "object"
    }
  },
  "properties": {
    "steps": {
      "description": "Ordered implementation steps",
      "items": {
        "$ref": "#/$defs/PlanStep"
      },
      "title": "Steps",
      "type": "array"
    },
    "title": {
      "description": "Short name for the overall plan",
      "title": "Title",
      "type": "string"
    }
  },
  "required": [
    "title",
    "steps"
  ],
  "title": "PresentPlanAction",
  "type": "object"
}
```

## `ask_user`

Ask the user one to four multiple-choice questions to clarify ambiguous requirements before you act. Provide each question's text, a short header, and 2+ options; set multi_select when several answers are valid. Prefer this over guessing when the task could reasonably go more than one way. Calling this pauses the turn until the user answers.

```json
{
  "$defs": {
    "Question": {
      "properties": {
        "header": {
          "default": "",
          "description": "A short label for the question (a few words), shown as a heading.",
          "title": "Header",
          "type": "string"
        },
        "multi_select": {
          "default": false,
          "description": "Whether the user may pick more than one option.",
          "title": "Multi Select",
          "type": "boolean"
        },
        "options": {
          "description": "The choices to offer. The user may also reply with their own answer.",
          "items": {
            "type": "string"
          },
          "minItems": 2,
          "title": "Options",
          "type": "array"
        },
        "question": {
          "description": "The full question to ask the user.",
          "title": "Question",
          "type": "string"
        }
      },
      "required": [
        "question",
        "options"
      ],
      "title": "Question",
      "type": "object"
    }
  },
  "properties": {
    "questions": {
      "items": {
        "$ref": "#/$defs/Question"
      },
      "maxItems": 4,
      "minItems": 1,
      "title": "Questions",
      "type": "array"
    }
  },
  "required": [
    "questions"
  ],
  "title": "AskUserAction",
  "type": "object"
}
```

## `web_research`

Delegate a web research task to a read-only specialist agent. Use this when you need documentation, API references, changelogs, Stack Overflow answers, or other public web information outside the workspace. The specialist searches with Tavily, fetches relevant pages, and returns a structured summary with source URLs.

```json
{
  "properties": {
    "description": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "description": "Optional short label (3-5 words) for the research task.",
      "title": "Description"
    },
    "prompt": {
      "description": "The web research task to investigate and summarize.",
      "title": "Prompt",
      "type": "string"
    }
  },
  "required": [
    "prompt"
  ],
  "title": "WebResearchAction",
  "type": "object"
}
```
