# Tool catalog

Generated by `uv run python -m miniagent.tools.catalog`. This is exactly what the model sees for each built-in tool; MCP tools are added at runtime.

## `bash`

Run a shell command and return its stdout, stderr, and exit code. The command runs non-interactively with the workspace root as the working directory. Use it for git work (`git log --oneline -10`, `git diff`), skimming a slice (`sed -n '40,90p' file.py`), verification (`python -m pytest tests/test_x.py -x -q`) and multi-file work. Search with the `grep` and `glob` tools instead of `rg`, `grep` or `find`. Keep output small: prefer `| head -50` and narrow test invocations over full suites. Never start interactive commands (editors, REPLs, watch mode). The default `timeout` is 30 seconds; pass a larger value (120-600) for installs, builds, or test suites. Set `description` to a short summary of the command, and `workdir` instead of starting the command with `cd`. Before `rm` or `mv`, check the resolved target path, and guard variables with `${VAR:?}` so an empty value cannot widen the target. If the sandbox denies a command, do not retry the same effect another way.

```json
{
  "properties": {
    "command": {
      "title": "Command",
      "type": "string"
    },
    "description": {
      "default": "",
      "description": "5-10 word summary of what the command does, shown to the user.",
      "title": "Description",
      "type": "string"
    },
    "timeout": {
      "default": 30,
      "maximum": 600,
      "minimum": 1,
      "title": "Timeout",
      "type": "integer"
    },
    "workdir": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "description": "Directory to run in, relative to the workspace. Use instead of `cd x && ...`.",
      "title": "Workdir"
    }
  },
  "required": [
    "command"
  ],
  "title": "BashAction",
  "type": "object"
}
```

## `file_edit`

View, create, or edit a file in the workspace. command='view' returns the file's raw text exactly as stored (no line numbers); pass view_range=[start, end] (1-based, end -1 = EOF) for a slice. command='create' writes content to a new file (overwriting an existing file requires viewing it first). command='str_replace' replaces a unique old_str with new_str; old_str must match the raw file bytes exactly (copy from view output, never include line-number prefixes) and appear exactly once, so include enough surrounding context to be unique. Edit only files you have viewed with command='view' in this conversation; reading a file with bash (cat, sed, head) does not count. If a file changed since your last view, view it again before editing. Change files only with this tool, never with bash scripts, sed -i or redirects.

```json
{
  "properties": {
    "command": {
      "enum": [
        "view",
        "create",
        "str_replace"
      ],
      "title": "Command",
      "type": "string"
    },
    "content": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "title": "Content"
    },
    "new_str": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "title": "New Str"
    },
    "old_str": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "title": "Old Str"
    },
    "path": {
      "title": "Path",
      "type": "string"
    },
    "view_range": {
      "anyOf": [
        {
          "items": {
            "type": "integer"

        },
        {
          "type": "null"

  "type": "object"
}
```

## `grep`

Search file contents with a ripgrep regular expression. Returns matching lines with line numbers, grouped by file. Use this instead of `grep` or `rg` in bash. Narrow with `path` and `include`. Hidden files are searched; gitignored files are skipped. Output stops at 250 lines.

```json
{
  "properties": {
    "include": {
      "anyOf": [
        {
          "type": "string"
        },
        {
          "type": "null"
        }
      ],
      "default": null,
      "description": "Only search files matching this glob, e.g. '*.py' or '*.{ts,tsx}'.",
      "title": "Include"
    },
    "path": {
      "default": ".",
      "description": "File or directory to search. Relative paths resolve against the workspace.",
      "title": "Path",
      "type": "string"
    },
    "pattern": {
      "description": "Regular expression to search for (ripgrep syntax).",
      "title": "Pattern",
      "type": "string"
    }
  },
  "required": [
    "pattern"
  ],
  "title": "GrepAction",
  "type": "object"
}
```

## `present_plan`

Use this when planning mode is on: after exploring the code read-only, lay out the ordered steps, each with an imperative title, the files it touches, and a short description, then call this tool instead of editing files or finishing. The turn stops so the user can approve or refine the plan before you implement.

```json
{

    "PlanStep": {
      "properties": {
        "description": {
          "default": "",
          "description": "One or two sentences on what to do and why",
          "title": "Description",
          "type": "string"
        },
        "files": {
          "description": "Files this step touches",
          "items": {
            "type": "string"
          },
          "title": "Files",
          "type": "array"
        },
        "status": {
          "default": "pending",
          "enum": [
            "pending",
            "in_progress",
            "done"
          ],
          "title": "Status",
          "type": "string"
        },
        "title": {
          "description": "Imperative summary of the step, e.g. 'Add the lane column'",
          "title": "Title",
          "type": "string"
        }
      },
      "required": [
        "title"
      ],
      "title": "PlanStep",
      "type": "object"
    }
  },
  "properties": {
    "steps": {
      "description": "Ordered implementation steps",
      "items": {
        "$ref": "#/$defs/PlanStep"

      "description": "Short name for the overall plan",
```

## `memory`

Read and write your persistent memory, which is kept across conversations. /memories/user/ holds notes about the user that apply in every repository; /memories/repo/ holds notes about the current repository. Commands: `view` lists a directory or shows a file with line numbers (optional view_range); `create` creates or overwrites a file with file_text; `str_replace` replaces a unique old_str with new_str; `insert` adds insert_text after line insert_line (0 is the top); `delete` removes a file or directory; `rename` moves old_path to new_path. Keep one topic per file, update an existing file instead of adding a duplicate, and delete memories that turn out to be wrong.
